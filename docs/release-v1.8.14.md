# v1.8.14 —— 修复「N 网已删除的 mod 被说成『你没填 API key』」

## 你遇到的现象

- 有个**已经从 N 网删掉**的模组
- 以前显示「此 Mod 已被删除，无法查看」之类的
- 现在却显示**「你没有填 API key」** —— 但你确实填了

## 原因

工具把「查询失败」分成几类（站点挡住了 / 这个 mod 没了 / 你该去填 key …），
分类方式是**在错误文案里找关键字**。而 N 网对已删除的 mod 给的文案是：

> 这个 mod 被**隐藏/删除**，或你的 key 无权访问

分类时找的是 `被删除` 三个字 —— 文案里**没有**这三个字连在一起（是"隐藏/删除"），
于是**那条分支从来没生效过**。程序继续往下走，落到了跟"钥匙"有关的那一条：

> 需要 API key —— 到「设置…」里填

**所以你填了也没用 —— 它压根不是在说 key，只是文案里正好带了"key"这个词。**

## 这版改了什么

**1. 错误分类不再靠"找关键字"**

失败原因改由**产生它的地方打标签**（`gone` 这个 mod 没了 / `site` 站点挡住 /
`net` 网络 / `rate` 限流 / `no_key` 没填凭据 / `bad_key` 凭据无效 /
`noperm` 没权限 / `shape` 站点改版），界面只认这个标签。

> 这样以后文案怎么改都不会再让分类**静默失效** —— 这次的问题本质就是
> "改了个词，分类悄悄失灵了，而且没人发现"。

**2. 分支顺序按"你下一步该干什么"排**

先判「这个 mod 没了 / 站点不让查」，**最后**才判凭据问题。
以前凭据那一条排得靠前，会把前面几类全部吃掉。

**3. 区分「没填 key」和「key 无效」**

| 情况 | 以前 | 现在 |
|---|---|---|
| 真的没填 | 需要 API key | 需要 API key —— 到「设置…」里填 |
| **key 无效 / 过期** | 需要 API key | **N网 API key 无效或已过期 —— 到「设置…」换一个** |

一个让你去**填**，一个让你去**换**。以前都说成"需要 API key"，
你会拿着一个明明填着的输入框反复确认。

## 验证

带真实 key 实测（`_issue1_repro/verify_deleted_mod_fixed.py`）：

| mod | N 网返回 | 现在显示 |
|---|---|---|
| #17024（已删除） | 403 `Mod not available` | 这个 mod 在站上已经没有了（可能已删除/改名） |
| #2（已删除） | 403 `Mod not available` | 同上 |
| #99999999（不存在） | 404 `No Mod Found` | 同上 |
| #16493（正常） | 200 | 正常检查更新 |

顺带确认了一件重要的事：**N 网对"已删除"返回的是 403（不是 404）**，
和"你没权限看"是同一个状态码 —— 所以必须读响应体里的 message 才能分开。
这也是为什么以前的文案要把两种含义混在一句里（"被隐藏/删除，**或**你的 key 无权访问"）。
