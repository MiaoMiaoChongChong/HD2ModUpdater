# v1.8.12 —— 修复「我明明更新过了，它还一直说有更新」

这次修的是 [issue #1](https://github.com/MiaoMiaoChongChong/HD2ModUpdater/issues/1)。
感谢 [M0onee404](https://github.com/M0onee404) 提供了完整的诊断信息 —— 那份日志里
「版本 1.1（手动填的）」和「目录名里明明写着 1.2」并排出现，直接指出了原因。

## 你遇到的现象

- 更新检查页一直说某个模组「有更新」
- 你重新下载、安装了新版本，它**还是**说「有更新」

## 原因

工具判断「有没有更新」时需要一个**本地版本号**。绝大多数时候它是从磁盘上读出来的
（Arsenal 记的版本号、或模组文件夹名里的版本号），所以你更新了模组、它就跟着变。

但有一种情况不是：**你手工填过的版本号会被永久记住，并且优先级最高**。

也就是说 —— 当初你为了帮工具认出某个模组（或者版本号显示不对时），手工填了一个
版本号；那个值从此排在所有自动探测的结果前面。**哪怕你后来把模组更新了**，
它仍然拿那个旧值去比线上版本，于是永远报「有更新」。

最难受的是：**界面上完全看不出来**。「本地」那一列只显示一个数字，
你没法分辨它是「自动探测到的真实版本」还是「当初手动填的旧值」。

还有一个入口问题：以前只要打开「指定来源」点保存（哪怕你只是想修一下来源、
版本框一个字都没动），工具就会把当时的版本号**顺手记下来**。
所以这个「冻结」很容易在用户毫不知情的情况下发生。

## 这版做了什么

**1. 手工填的版本改成「跟着内容走」**

你填的版本号会连同「你填的那一刻，这个模组的内容」一起记下来：

| 情况 | 工具怎么做 |
|---|---|
| 模组内容没变 | 继续用你填的值 |
| **模组内容变了**（你更新过它） | **自动失效**，改回自动探测 |

所以「更新完了还一直催你更新」这个现象不会再出现了。

> 判定用的「内容签名」是自己算的：把模组目录里所有 `.patch_` 文件的
> 路径 + 内容一起哈希。之所以不用现成的信号，是因为实测它们都不可靠 ——
> Arsenal 自己记的哈希我们只能复现 16/21（多选项模组它的算法没解出来），
> 而文件修改时间有 8/21 是 `1980-01-01`（解包没带时间戳）。
> 全量算一遍 21 个模组、260MB 内容只要 0.21 秒。

**2. 界面上如实标出这个值从哪来**

「本地」列现在会写清楚：

- `1.2（自动）` —— 自动探测到的
- `1.1（手动）` —— 用你填的
- `1.2（旧值1.1已失效）` —— 你填的已经过期，现在按 1.2 判断

「说明」那一列也会讲清为什么这么判。
另外更新检查页右键多了一项**「本地版本…」**，那里同时列出三个值 ——
「现在采用的」「自动探测到的」「你手动填过的」，可以改，也可以一键恢复自动探测。

**3. 顺带修掉两个会让人白折腾的毛病**

- **只打开「指定来源」改来源、版本框没动时，不再把你的版本号冻住**。
- **把 ZIP 拖进来导入时，不再抹掉 Arsenal 自己记的模组信息** ——
  以前在没配 N 网 API key 的情况下会把那条信息清空，导致工具在
  「刚装完新版」的情况下仍然说有更新。
- 模组已经从库里删掉、手动记录还留着的，下次启动时自动清理。

## 对已有用户的影响

- **以前填过版本号、而且填得对、模组也没更新过的** → 行为完全不变，继续照用。
- **以前填过、后来更新过模组的** → 下次检查时自动失效、改用真实版本，
  工具会告诉你「你填的 X 已自动失效」。
- **v1.8.11 及更早填的（没有内容签名）** → **不会被丢弃**，仍然照用，
  但会标成「还没核对过内容」，你可以自己决定要不要改回自动。

## 验证

- 全套检查与测试：**1153 项全部通过**（新增 40 项专门钉住这次修的东西）
- 在真实模组库上只读复核 21 个模组：**误报 0 个**
