# v1.8.13 —— 修复合并部署后仍然显示「有更新」

这次修的是 v1.8.12 发布后你自己实测发现的问题。

## 你遇到的现象

- HD2Runtime 和 Vanilla Plus Megapack - v41 这两个模组，
  你已经**更新、导入、部署**过了
- 重新检查更新，仍然显示「有更新」

## 原因（和 v1.8.12 那个不是同一个问题）

导入更新版时，为了**不删你的旧数据**，工具会**沿用原来的文件夹**。
旧内容会先挪到 `.hd2u-old-` 备份，这是有意为之的安全设计。

代价是：**文件夹名不会跟着版本变**。

于是就出现了这种情况：

| | 版本号 |
|---|---|
| 文件夹名（一直停在旧版） | `Vanilla-Plus-Megapack-v40` / `HD2Runtime-0.30.3` |
| 里面实际装的内容 | v41 / 0.31.3 |

而工具判断「本地版本」时**优先读文件夹名**，所以永远读到 40 / 0.30.3，
和线上的 41 / 0.31.3 一比，就说"有更新"。

> 为什么这两个模组特别明显：它们**不是从 N 网装的**，Arsenal 库里的
> `nexusData` 是空的，所以工具只能退回去读文件夹名 —— 而那正好是旧值。

## 这版改了什么

**1. 导入那一刻就把「现在装的是哪个版本」记下来**

导入是我们**最确切知道版本**的时刻。比事后从文件夹名或 mod 自带文件里猜可靠得多
（实测有些 mod 的自带文件里反而写着更旧的号）。

这条记录**也带内容签名** —— 以后你再更新一次，它同样会自动失效，
不会变成第二个"永久冻结"。

**2. 存量兜底：两处证据不一致时，取更新的那个**

文件夹名和 mod 自带文件里的版本号不一致时，取更新的那个。

**所以这一版你不用重新导入** —— 已经中招的模组装上就会自己好起来。

## 一个不需要担心的显示

`机甲部位血量HUD v1.11.1` 的本地版本显示成 `1`，这是**正确的**：
那个 mod 在 N 网上登记的版本号就是 `1`，`v1.11.1` 是作者写在 mod 显示名里的。
工具以 N 网的登记为准。

- 全套检查与测试：**1165 项全部通过**（v1.8.12 是 1153 项，本次新增 12 项）
- 按你实测的两个 mod 的真实场景（目录名 0.30.3/40、实际 0.31.3/v41）回归验证：已正常
- 在你的真实模组库（21 个）上只读复核：**误报 0 个**
